No-API-Key Workflow

Working Without an API Key

Plan Console 1.0.0 — the complete copy-paste workflow for people who do not have (or do not want) an OpenRouter API key. Everything below works fully offline, costs nothing, and uses no external services.

1. Do I need an API key?

No. The OpenRouter API key is entirely optional. Plan Console is built agent-agnostic: it hands ready-made instructions to your coding agent (Zoo Code, Claude Code, Cursor, Codex, or any other), which does the actual work inside your repository. Without a key the app is not a "demo mode" — it is the full product.

What the key adds

  • The Model picker in the top bar can fetch the live OpenRouter model list.
  • Optionally, the console itself can call the model to scaffold the first draft (PART-01.draft.md, RECON-CHECKLIST.md, OPEN-QUESTIONS.md) instead of you pasting an instruction into your agent.

What works without it — everything else

  • Pointing Repo folder at a project and Init starter repo.
  • The Intake tab: pasting a plan / brainstorm / audit, and saving it as plans/<slug>/SOURCE.md.
  • Copying the ready-made instruction for your coding agent — the console generates the exact text, you paste it, the agent scaffolds the plan files in your repo.
  • The whole Owner pass tab: answering open questions, ticking the recon checklist, running whitelisted read-only owner actions.
  • Validate draft, Auto-resolve findings and Freeze (with all its safety gates).
  • The entire Sessions loop: session instructions, verdicts, plan health.
  • Themes, window size, sample project — all key-free.

Security note: the key is never written to disk. It lives in memory for the current session only (legacy stored keys are removed on load). Without a key, nothing leaves your machine except what you yourself paste into your agent.

2. Quick start without a key

The end-to-end path from zero to a finished plan, with no key anywhere:

  1. Start the app — double-click plan.bat (or run python plan-console.py). Leave the API key field in the top bar empty and leave "use key" unticked. You never need to touch either.
  2. Point Repo folder (top bar, Browse…) at your project folder — the folder whose code your agent will work on. First time? Create an empty test folder, or use the bundled sample project (see section 7).
  3. Click Init starter repo. This writes PART-00.md (the rulebook), templates/ and commands/ into your repo. Existing files are never overwritten.
  4. Open the Intake tab. Paste your plan, brainstorm or audit report into the big text box. Pick the Type (plan, brainstorm or audit) and type a short Slug — lowercase-with-dashes, e.g. payments-v2.
  5. Click Proceed. Your text is saved as plans/<slug>/SOURCE.md and a popup appears with a ready-made instruction. Copy it (there is a copy button; a backup also lands in plans/<slug>/instructions/).
  6. Paste the instruction into your coding agent (Zoo Code, Claude Code, Cursor, Codex, …) with your repo folder open as the workspace. The agent scaffolds PART-01.draft.md, RECON-CHECKLIST.md and OPEN-QUESTIONS.md in plans/<slug>/.
  7. Owner pass — answer the open questions and tick the recon checklist (see section 4).
  8. Validate draft → fix gaps → Freeze. You now have PART-01 v1.0.md, the locked official plan.
  9. Sessions tab — copy the session instruction, paste it into your agent, repeat until Plan health says PLAN COMPLETE.

That is the whole loop: Intake → copy instruction → agent works → owner pass → validate → freeze → sessions → plan complete. The console never needs to talk to a model; every hand-off goes through your clipboard and files in your own repo.

3. The agent-instruction loop

The console and your agent never talk to each other directly. Communication happens through the clipboard and through files in your repository:

Console → Agent: ready-made instructions (copied to your clipboard or saved under plans/<slug>/instructions/)

Agent → Console: files the agent writes back into plans/<slug>/ — the console always re-reads and checks them afterward, so half-finished work gets caught.

Every instruction the console produces is self-contained: it tells the agent which rules file to load (PART-00.md), which files to read, exactly which files to write, and in which format. The same mechanism works with any capable coding agent.

What the agent does per intake type

Intake type You paste The agent writes back
plan A finished plan / task description PART-01.draft.md (the plan in the standard form), RECON-CHECKLIST.md, OPEN-QUESTIONS.md
brainstorm Rough ideas, options, notes Same three files — the agent distills the brainstorm into a coherent draft plan, listing what still needs your decision
audit An audit report with findings The same three files plus TRIAGE.md, which sorts every finding into fix-now / fix-later / accept

In all three cases the draft's ## Owner actions section and OPEN-QUESTIONS.md are where the agent parks anything only you can decide — that is what the next step is for.

4. The owner pass without a key

Open the Owner pass tab, type the slug, click Refresh. The tab loads the plan's open questions, owner actions and recon checklist. None of this needs a key:

  • Open questions. Questions the agent could not answer itself. If a question carries a RECOMMEND: line (shown with a ·has rec suffix) and you agree with it, select it and click Accept recommendation — one confirmed click saves it as your answer. Otherwise type your answer in the answer box and click Save answer → draft + remove. Answers land in plans/<slug>/PART-01.draft.md under ## OWNER ANSWERS and the question is removed from OPEN-QUESTIONS.md (a .bak snapshot is kept, and the exchange is archived to owner-pass.log).
  • Recon checklist. Items the agent could already verify are ticked [x] for you. Items left for you: run the check, then change [ ] to [x] in RECON-CHECKLIST.md (or delete lines you decide to skip). Freeze is blocked while any [ ] remains.
  • Owner actions (right-hand panel). Commands the agent must never run — anything needing your passwords, dashboards or owner-only files, listed from ## Owner actions in OPEN-QUESTIONS.md.
    • Whitelisted read-only commands (Select-String, Test-Path, Get-Content, git status/diff/log) get a Run (read-only) button: the console runs the command in your repo, shows the output in the log, and — after you confirm — marks the linked §B line VERIFIED <today> in the draft and ticks the action done.
    • Anything else: Copy command, run it in your own terminal, then Mark done.
    • Nothing runs or is written without your confirmation; every event goes to owner-pass.log.

Not sure why Freeze is refusing? Click What's blocking Freeze? — a read-only dry-run that lists exactly what would block Freeze right now, without changing anything.

5. Validate, auto-resolve and freeze without a key

Validate draft

Click Validate draft. Without a key the console copies one ready-made instruction; paste it into your agent and the agent writes a gap-report to plans/<slug>/VALIDATION.md (verdict + every gap it found). Click Show validation report to read it in the console log.

Auto-resolve findings

Auto-resolve findings parses VALIDATION.md and chains the remediation for you. Without a key it copies one ready-made instruction that makes the agent do both steps back-to-back: answer/fix the findings (owner-resolve) and then re-validate. Paste it, let the agent finish, and the fresh report supersedes the old one. When "auto-resolve findings" is ticked, this also chains automatically after Validate draft.

Freeze — the gates

Freeze is instant and involves no agent, but it is deliberately gated. It refuses (with a clear message) unless all of these hold:

  • 0 open questions in OPEN-QUESTIONS.md
  • 0 unchecked recon items ([ ]) in RECON-CHECKLIST.md
  • 0 unchecked owner actions
  • VALIDATION.md verdict is exactly "PART-01 READY"

When it succeeds, PART-01 v1.0.md is created — the locked official plan with its session list. Frozen means locked. If you must change it later, edit it and add " | v1.1 frozen <date>" to its first line, and note why in PROGRESS.md.

6. Sessions without a key

The session loop is 100% key-free by design — sessions always run in your agent, with whatever model you chose there.

  1. Open the Sessions tab. Type the slug, set the session number (start with 1).
  2. Click Copy session instruction. The instruction embeds your standing orders from AGENT-ORDERS.md (edit them any time via Agent orders… in the top bar — things like "always write tests", "never push to main") plus the exact scope of this session.
  3. Paste it into your agent (repo open as the workspace) and let it work. The agent records its completion when done.
  4. Back in the console, click Session report. You get a verdict:
    • OK — session complete. The session number advances by 1 automatically (never past the deploy session).
    • ⚠ CHECK — something's off (usually a completion line not in the exact required format). A "fix:" hint is shown and copied to your clipboard — paste it into your agent and click Session report again.
    • ✖ BLOCKED — the agent wrote BLOCKED.md explaining what stopped it and what it tried. Fix the cause (often you must run a command or provide access), rename BLOCKED.md to BLOCKED-resolved.md, and re-run the session.
    • ✖ INCOMPLETE — no completion record at all; the session never finished.
  5. Repeat until the last session — the deploy session (marked [DEPLOY] in the plan). Run it the same way but stay and watch: the agent runs checks before and after deploying, and stops immediately if a post-deploy check fails.

You cannot jump ahead: session 3 will not run before sessions 1 and 2 have OK records. That is deliberate — plans die from skipped steps.

Plan health — click any time for one line per session: what's done, what's broken, what's next. Always click it before the deploy session (the "pre-deploy sweep") and when returning to a plan after a break. Every health run is appended to plans/<slug>/HEALTH.md. Status is the quicker one-line "where am I". When all sessions pass, health tells you to write PLAN COMPLETE — paste that hint into your agent or add the line to PROGRESS.md yourself. The plan is done.

7. See it live in 5 minutes (sample project)

The fastest way to understand the workflow — no key and no agent needed — is the bundled sample project, new in this release.

  1. On the Intake tab, click Open sample project….
  2. Choose an empty folder. The console copies the bundled samples/demo-project/ there and points Repo folder at it.
  3. Explore the two bundled plans:
    • plans/demo-recipe-cli — a finished example: frozen plan (PART-01 v1.0.md), completed recon checklist, answered questions, a VALIDATION.md that says PART-01 READY, and a PROGRESS.md/​HEALTH.md history. This is what "done" looks like.
    • plans/demo-journal-wip — a mid-workflow example: draft in progress with open questions still unanswered and recon items still unticked. Use it to exercise the Owner pass tab, What's blocking Freeze? and the freeze gates safely.
  4. Try it out: click Refresh in the Owner pass tab on the demo-journal-wip slug, answer a question, tick a recon item, then click What's blocking Freeze? to watch the blocker list shrink.

8. Troubleshooting (no-key specific)

Problem Fix
A copy button "did nothing" — nothing lands in the clipboardSome window managers block clipboard access from Tk. Use the popup's text area: select all, copy manually (Ctrl+C). Every instruction is also saved under plans/<slug>/instructions/ — open the file and copy from there.
The agent didn't create the plan filesCheck the agent had your repo folder open as the workspace (not a parent or subfolder), that it actually finished, and that the slug matches. Re-copy the instruction from plans/<slug>/instructions/ and paste it again — the instructions are idempotent, re-running them is safe.
The agent created files in the wrong placeMove them into plans/<slug>/ yourself; the console re-reads the folder on Refresh. The instruction always names the exact target paths.
Owner pass tab shows no questionsWrong slug, or the agent never wrote OPEN-QUESTIONS.md. Verify the folder plans/<slug>/ exists in the repo and click Refresh.
"Not a plan repo" popupStarter files are missing in the chosen folder — click Init starter repo (it never overwrites existing files).
Freeze is blockedIt tells you exactly what's open. Click What's blocking Freeze? for the full list: unanswered questions, unticked recon [ ] items, unchecked owner actions, or a VALIDATION.md verdict that is not PART-01 READY.
Validation keeps coming back not-READYClick Auto-resolve findings and paste the single combined instruction (fix + re-validate) into your agent; iterate until the report says PART-01 READY.
Session report says "not canonical"The agent wrote its completion line in the wrong format. The "fix:" hint is already on your clipboard — paste it into your agent, then click Session report again.
Model list is empty / "Reload models" does nothingExpected without a key — the live list comes from OpenRouter. You don't need it: your agent uses its own model. You can also type a model id by hand.
Sample project button did nothingChoose an empty (or new) folder; the copy is aborted if the target already contains conflicting files. Then check the new folder was pointed at as Repo folder.
Want to reset everythingDelete plan-console.json (settings only) — plans live in your repo and are untouched.

General (key-or-not) issues — window doesn't open, session order, deploy — are covered in the main User Guide.

9. FAQ

Is the app crippled without a key?

No. The key only changes who scaffolds the first draft: the console's model call, or your own agent via a pasted instruction. Every other feature — owner pass, validation, freeze gates, sessions, plan health — is identical with or without a key.

Which agents can I use?

Any capable coding agent: Zoo Code, Claude Code, Cursor, Codex, and others. The instructions are plain text with explicit file paths and formats, so nothing is tied to one product.

Does anything get sent to the internet without a key?

No. Without a key the console makes no network calls at all. The only data leaving your machine is what you yourself paste into your agent, under your control.

Is my API key safe if I later add one?

Yes — the key is kept in memory for the current session only and is never written to disk. Legacy keys found in the settings file are removed on load.

Can I mix modes — key for intake, agent for sessions?

Yes. Sessions always run in your agent regardless. The key only affects the intake scaffolding step; you can start some plans key-free and others with a model call, in the same repo.

What if my agent writes a bad or lazy draft?

The console always re-reads and checks what the agent wrote. The freeze gates (zero open questions, zero unticked items, PART-01 READY validation) exist precisely to catch half-finished work before a plan is locked.

Do free OpenRouter models change anything?

If you later add a key, models ending in :free cost nothing — but that path is entirely optional. The copy-paste loop is the zero-cost path and always available.

Where do I learn the full workflow (including key usage)?

See the main User Guide (UserGuide.html) in the app folder — it covers the key-based intake, the button reference, and the file meanings in detail.
